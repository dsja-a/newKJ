## 1. 项目概述

科吉（Keji）是一款面向企业内网的 **本地 / 局域网 AI 助手**。浏览器打开即可对话，支持多账号、团队共享文件夹、管理员后台。适合办公室内网一台服务器、多人通过网页访问的场景。

科吉的 Agent 引擎基于开源项目 [nanobot](https://github.com/HKUDS/nanobot)（HKUDS，MIT 许可），在其上增加了 Web 前端、多用户权限、团队文件工作区与企业部署能力。

### 设计理念

- **本地优先**：支持 Ollama 本地模型，数据不外传
- **轻量部署**：单机可运行，无需复杂配置
- **工具链完整**：文档生成、表格处理、PPT、OCR、邮件、知识库、文件管理

## 3. 快速开始

### 3.1 前置条件

| 软件 | 必须 | 说明 |
|------|------|------|
| Python 3.12（64 位） | 是 | 安装时勾选 **Add to PATH** |
| Git + Git LFS | 是 | 克隆代码并拉取离线依赖 |
| Node.js 18+ | 否 | 完整 MCP 能力，不装也能聊天 |

### 3.2 一键部署

```powershell
git clone https://github.com/Zuofeng198/keji.git
cd keji
git lfs install
git lfs pull
# 双击 setup_deploy.bat，或：
.\setup_deploy.bat
```

部署脚本会自动：
1. 创建 Python 虚拟环境 `venv/`
2. 从离线 wheel 或 PyPI 安装依赖
3. 生成 `config.yaml` 和 `.env`
4. 创建数据目录

### 3.3 配置密钥

编辑 `.env`，至少填写：

```env
DEEPSEEK_API_KEY=sk-你的DeepSeek密钥
KEJI_ADMIN_PASSWORD=你的管理员密码
```

### 3.4 启动

| 方式 | 操作 |
|------|------|
| 推荐 | 双击 **`launch_keji.bat`** → 自动打开浏览器 |
| 看日志 | 双击 **`run_server.bat`** → 黑窗运行 |

- 本机访问：http://127.0.0.1:8000/
- 局域网访问：http://服务器IP:8000/

### 3.5 登录

默认管理员账号：

| 字段 | 默认值 |
|------|--------|
| 用户名 | `admin` |
| 密码 | `.env` 中 `KEJI_ADMIN_PASSWORD` 的值 |

## 4. 架构设计

### 4.1 整体架构

```
┌──────────────────────────────────────────────────────┐
│                    Web 前端 (SPA)                      │
│    index.html → core.js / chat.js / pages.js ...      │
└─────────────────────┬────────────────────────────────┘
                      │ SSE / REST API
                      ▼
┌──────────────────────────────────────────────────────┐
│                  FastAPI 服务层                        │
│  main.py (入口) → core/routes.py (路由注册)             │
│  ├─ /chat/stream    对话 SSE 流                       │
│  ├─ /auth/*         JWT 登录/登出/验证                 │
│  ├─ /admin/*        用户管理/会话管理                  │
│  ├─ /api/*          文件/知识库/数据库等 REST 接口       │
│  └─ /static/*       前端静态资源                        │
└─────────────────────┬────────────────────────────────┘
                      │
                      ▼
┌──────────────────────────────────────────────────────┐
│               nanobot Agent 引擎                        │
│                                                       │
│  adapter.py (科吉 ↔ nanobot 胶水层)                    │
│  ├─ AgentRunner (ReAct 工具循环)                       │
│  │  ├─ 调 LLM → 解析意图 → 执行工具 → 继续/返回        │
│  │  ├─ 上下文治理（压缩/截断/去孤儿 tool_result）       │
│  │  └─ 工具执行（内置 35+ 工具 + MCP 外部工具）         │
│  ├─ LLM Provider 层                                   │
│  │  ├─ OpenAI 兼容 API（DeepSeek / Ollama）             │
│  │  └─ Anthropic Claude 原生 SDK                      │
│  ├─ 工具系统（ToolRegistry）                            │
│  │  ├─ 内置工具：文档/表格/OCR/邮件/代码/搜索           │
│  │  └─ MCP 客户端：连接外部工具市场                      │
│  └─ Session 管理器                                     │
│     └─ 会话持久化（JSONL 文件）                         │
└─────────────────────┬────────────────────────────────┘
                      │
                      ▼
┌──────────────────────────────────────────────────────┐
│                 数据与存储层                             │
│                                                       │
│  data/keji.db        SQLite（用户/会话/设置/文档索引）   │
│  data/vector_db/     ChromaDB（知识库向量存储）         │
│  data/workspace/     团队文件工作区                     │
│  sessions/           对话会话 JSONL                     │
│  logs/               运行日志/审计日志                   │
│  knowledge/          知识库源文件                       │
└──────────────────────────────────────────────────────┘
```

### 4.2 数据流

```
用户 → index.html → sendChat() → POST /chat/stream
                                        │
                                  adapter.chat_stream()
                                        │
                                  AgentRunner.run(ReAct 循环)
                                        │
                              ┌─────────┴──────────┐
                              ▼                    ▼
                         LLM (DeepSeek/Ollama)   Tool 执行
                              │                    │
                              └─────────┬──────────┘
                                        ▼
                                   SSE 事件流
                                   │
                          think_token → 思考面板 + 状态条
                          answer      → AI 回答气泡
                          done        → 清理
```

### 4.3 SSE 事件类型

| 事件 | 触发时机 | 前端处理 |
|------|----------|----------|
| `think_token` | LLM 思考 / 工具调用 | 更新思考面板 + 状态条 |
| `answer` | 最终回答 | 追加到 AI 回答气泡 |
| `error` | 出错 | Toast 提示 |
| `done` | 流结束 | 清理 + 停止计时器 |

## 5. 核心模块说明

### 5.1 Web 前端（`web/`）

SPA 单页应用，6 个 JS 文件通过 `<script>` 标签加载：

| 文件 | 职责 |
|------|------|
| `core.js` | 全局变量、双图标系统、通用函数 |
| `chat.js` | 核心：`sendChat` SSE 流处理、消息气泡渲染 |
| `pages.js` | 知识库、文件浏览、设置、数据库、智能问数 |
| `init.js` | 启动初始化（checkStatus、加载配置） |
| `history.js` | 历史对话、分屏、多选删除 |
| `debug.js` | 调试面板（事件/工具/日志/JSON） |

### 5.2 Agent 引擎（`nanobot/`）

| 模块 | 文件 | 重要性 | 说明 |
|------|------|:------:|------|
| 胶水层 | `adapter.py` | ★★★ | 科吉的核心：工具注册、SSE 流生成、MCP 连接 |
| 运行器 | `agent/runner.py` | ★★★ | ReAct 工具循环引擎 |
| MCP 客户端 | `agent/tools/mcp.py` | ★★★ | 连接外部工具市场 |
| 工具注册表 | `agent/tools/registry.py` | ★★ | 工具注册/查找/执行 |
| Tool 基类 | `agent/tools/base.py` | ★★ | 所有工具继承 |
| LLM 适配 | `providers/openai_compat_provider.py` | ★★ | DeepSeek/Ollama 等模型调用 |

### 5.3 后端服务（`core/`）

| 模块 | 说明 |
|------|------|
| `routes.py` | 主 API 路由（对话、文件、知识库等） |
| `routes_auth.py` | JWT 登录/登出/验证 |
| `routes_admin.py` | 管理员路由（用户管理、会话查看） |
| `routes_security.py` | 安全设置相关 |
| `security/` | 鉴权、审计、用户管理、权限控制 |
| `database/db.py` | SQLite 数据库管理 |
| `document/` | 文档解析器（PDF/Word/Excel/PPT）与知识库索引 |
| `rag/` | 向量嵌入 + ChromaDB 向量存储 |
| `skills/` | 技能加载器与注册 |
| `wechat/` | 微信桥接（个人微信 iLink + 企业微信） |

## 7. 配置说明

### 7.1 配置文件

| 文件 | 作用 | 是否提交 Git |
|------|------|:------------:|
| `.env` | API Key、管理员密码、JWT 密钥 | 否 |
| `config.yaml` | 模型、MCP、安全策略等全局配置 | 否 |
| `config.example.yaml` | 配置模板 | 是 |

### 7.2 核心配置项

**安全配置（`config.yaml` → `security`）：**

```yaml
security:
  enabled: true
  auth_mode: both
  jwt_expire_hours: 72
  filesystem_sandbox: true           # 全局文件沙箱
  bootstrap_admin:
    username: admin
    password: ${KEJI_ADMIN_PASSWORD}
```

**模型配置（`config.yaml` → `models`）：**

```yaml
models:
  default: deepseek
  deepseek:
    base_url: https://api.deepseek.com
    api_key: ${DEEPSEEK_API_KEY}
    model: deepseek-v4-flash
  openai:
    base_url: https://api.openai.com/v1
    model: gpt-4o-mini
  ollama:
    base_url: http://localhost:11434
    model: qwen2.5:7b
```

**Agent 参数：**

```yaml
agent:
  max_tool_rounds: 80
  max_history_tokens: 131072
  temperature: 0.7
  stream: true
  use_knowledge: true
  tool_timeout: 120
```

### 7.3 MCP 服务器

科吉通过 MCP（Model Context Protocol）连接外部工具：

| 服务 | 包名 | 功能 |
|------|------|------|
| filesystem | `@modelcontextprotocol/server-filesystem` | 文件系统操作 |
| memdb | `@j0hanz/memdb` | 内存数据库 |
| excel | `@negokaz/excel-mcp-server` | Excel 处理 |
| charts | `mcp-echarts` | 图表生成 |
| doc-tools | `@puchunjie/doc-tools-mcp` | 文档工具 |
| image-gen | `@pollinations/model-context-protocol` | 图片生成 |
| quack | 本地 DuckDB MCP | 数据分析 |

## 8. 角色与权限

| 角色 | 对话工具 | 文件访问 |
|------|----------|----------|
| **admin** | 全部工具 | 整个工作区（所有用户的目录） |
| **member** | 可写工具 | 共享目录 + 自己的 `users/<id>/` |
| **readonly** | 仅读/查询类工具 | 仅读共享目录 + 自己的目录 |

**团队文件物理路径：**

```
data/workspace/
  shared/          ← 全员可见（只读角色不可写）
  users/
    <用户ID>/      ← 仅本人 + 管理员可访问
```

## 9. 部署指南

### 9.1 标准部署

参见 [快速开始](#3-快速开始) 部分。

### 9.2 离线部署

适用于**完全无互联网**的内网环境：

```powershell
git clone https://github.com/Zuofeng198/keji.git
cd keji
git lfs install
git lfs pull      # 拉取约 400MB 离线 wheel
.\setup_deploy.bat  # 使用本地 wheel，不联网
```

若需变更 Python 版本，运行 `package_wheels.bat` 重新打包。

### 9.3 局域网共享

- 服务默认监听 `0.0.0.0:8000`
- 其他电脑访问 `http://服务器内网IP:8000/`
- 若不通：检查 Windows 防火墙是否放行 TCP 8000 端口

### 9.4 防火墙放行

```powershell
New-NetFirewallRule -DisplayName "Keji Agent 8000" `
  -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
```

### 9.5 停止服务

```powershell
# 方法 1：任务管理器结束 pythonw.exe
# 方法 2：命令行
Get-NetTCPConnection -LocalPort 8000 -ErrorAction SilentlyContinue |
  ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

### 9.6 Docker（未来规划）

目前为原生 Windows 部署，Docker 支持在路线图中。

### 10.3 内置工具开发

工具集成在 `nanobot/agent/tools/` 下，新工具需：

1. 继承 `base.py` 中的 `Tool` 基类
2. 定义 `name`、`description`、`parameters` 和 `execute()` 方法
3. 在 `adapter.py` 的 `_build_tools()` 中注册

### B. 故障排查

| 现象 | 处理 |
|------|------|
| 网页无法访问 | 确认服务在跑、端口 8000、防火墙放行 |
| 登录掉线 | 检查 `.env` 中 `KEJI_JWT_SECRET`；清浏览器缓存 |
| 对话无回复 | 检查 `DEEPSEEK_API_KEY` 有效性及余额 |
| 工具报权限 | 确认账号角色；只读角色不可用写入工具 |
| 团队文件 403 | 路径不在该用户允许的工作区 |
| pip 安装失败 | 确认 Python 为 64 位；重跑 `setup_deploy.bat` |
